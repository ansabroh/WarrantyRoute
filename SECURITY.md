# Security and trust boundaries

- Issuer controls initial registrations only; warranties cannot be edited or deleted. Each deployment represents one issuer. Binding an account does not establish a real-world manufacturer identity.
- Only the registered claimant files a claim; only its designated service provider can attest an immutable service report. Attestation proves account authorization and commitment to bytes, not truth of the underlying inspection. Collusion, compromised keys and fabricated real-world documents remain possible.
- All source text and claimed defects are hostile input. Prompts separate task instructions from JSON data; exact schema, item order, enums, byte hashes and quotations are enforced. Validators perform independent assessment and a second contextual audit. Prompt injection and shared model mistakes cannot be ruled out.
- Only commit-pinned GitHub raw plaintext is allowed. Hash/length mismatches, decoding errors, retrieval failures and malformed AI reviews yield INCONCLUSIVE. Validator disagreement rejects the transaction; it is not silently converted into a recorded consensus outcome.
- Dates and numeric bounds reject booleans. Reporting day comes from deterministic chain time; onset must be verified semantically. Original coverage terms take precedence over allegations; contradictions yield uncertainty. Contractual assessment does not determine statutory rights.
- JSON rejects duplicate keys and extra fields. Canonical ASCII JSON and SHA-256 bind each receipt to immutable warranty, claim, report and previous receipt. No state-mutating admin override, value transfer, payout, refund, or upgrade methods exist.
- Retry cap applies to committed assessments, not failed network transactions. Duplicate exact claims under one warranty are rejected; reworded duplicate claims are not semantically deduplicated. No payment flow exists for them to exploit. Global storage grows with registrations/claims and is subject to network fees and resource limits.
- No on-contract challenge or evidence amendment flow. New independent evidence requires a new claim, preserving the original history. Organizational dispute resolution and manufacturer identity verification are integration responsibilities.

Report issues privately to the repository owner before sharing exploit details.
